# პირადი RS.GE კონექტორი

ლოკალური MCP კონექტორის პროტოტიპი მცირე ბიზნესის ყოველთვიური დეკლარაციის მოსამზადებლად. კურსისა და აღრიცხვის ნაწილი მუშაობს. RS.GE-ის ფორმის შევსების ადაპტერი დაწერილია, მაგრამ რეალური თანხებით ჯერ არ არის გამოცდილი. ამ ვერსიას დეკლარაციის გაგზავნის ინსტრუმენტი არ აქვს.

## როგორ მუშაობს

ასისტენტს ეუბნები ჩარიცხვის სრულ თარიღს, თანხას და ვალუტას. კონექტორი ეროვნული ბანკიდან იღებს იმ თარიღისთვის მოქმედ ოფიციალურ კურსს, თანხას ლარში გადაიყვანს და ადგილობრივ აღრიცხვაში შეინახავს. რამდენიმე ჩარიცხვისას თითოეული თავისი დღის კურსით გადაიყვანება და შემდეგ თვის თანხები ჯამდება.

დეკლარაციისთვის საჭიროა თვის სრული ბიზნესშემოსავალი და წლის დასაწყისიდან წინა თვის ჩათვლით გადამოწმებული ჯამი. უცნობი წინა ჯამი ნულად არ ითვლება. ჩანაწერის მუდმივი იდენტიფიკატორი განმეორებით დათვლას იცავს.

შევსების ადაპტერი გათვალისწინებულია საკასო მეთოდით აღრიცხული საბანკო ბიზნესშემოსავლისთვის: წლის ჯამი მე-15 ველში, თვის საბანკო თანხა მე-20 ველში. გადასახადი იკითხება RS.GE-ის ავტომატური გაანგარიშებიდან. სხვა შემოსავლების, შეღავათების, ხელფასების, რეგიონული განაწილების ან დარიცხვის მეთოდის აღმოჩენისას ეს გზა შევსებას არ აგრძელებს.

## ავტორიზაცია

`open_rs_browser` ხსნის Edge-ის ცალკე ფანჯარას. მომხმარებელი უშუალოდ RS.GE-ზე შეიყვანს პაროლსა და SMS კოდს. კონექტორი მათ არ იღებს და სესიას ფაილში არ ინახავს. სესიის გათიშვის ან კონექტორის თავიდან გაშვების შემდეგ ხელახლა შესვლაა საჭირო. კურსის მიღება და ადგილობრივი აღრიცხვა RS.GE-ზე შესვლის გარეშეც მუშაობს.

ამ ვერსიაში ფორმის პირველადი გახსნა ხელით ხდება: მენიუ → დეკლარაციები → ყოველთვიური → მცირე ბიზნესის საშემოსავლო გადასახადი → პერიოდი → ახალი დეკლარაცია. ახალი ფორმის გახსნისას RS.GE-მ შეიძლება ცარიელი მონახაზი ავტომატურად შექმნას; განმეორებით გახსნამდე არსებული მონახაზი უნდა შემოწმდეს.

## ინსტრუმენტები

| ინსტრუმენტი | დანიშნულება |
|---|---|
| `get_connector_status` | შესაძლებლობებისა და შეზღუდვების ჩვენება |
| `convert_receipt` | კურსის მიღება და გადაყვანა, შენახვის გარეშე |
| `record_business_income` | ბიზნესშემოსავლის ადგილობრივად აღრიცხვა |
| `get_month_summary` | თვის ჩარიცხვები და ლარის ჯამი |
| `prepare_monthly_declaration` | თვისა და წლის ჯამების მომზადება |
| `open_rs_browser` | Edge ფანჯრის გახსნა ავტორიზაციისთვის |
| `inspect_rs_form` | ანგარიშის, პერიოდისა და ველების წაკითხვა |
| `fill_rs_form` | მხოლოდ მე-15 და მე-20 ველების შევსება |

`fill_rs_form` არც „შენახვა“ და არც „გადაგზავნა“ ღილაკს არ იყენებს.

## ლოკალური დაყენება Windows-ზე

საჭიროა Python 3.11+ და Microsoft Edge. პროექტის საქაღალდეში გაუშვი:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`codex-config.example.toml` ან `mcp-config.example.json` ფაილში შეცვალე გზები შენი პროექტის გზებით. კლიენტის არსებულ კონფიგურაციას ემატება მხოლოდ `personal_rs` სერვერი. ჩვეულებრივი Python გარემოსთვის `RS_MCP_RUNTIME` საჭირო არ არის; იგი სურვილისამებრ გამოიყენება `pip --target` დამოკიდებულებების გზისთვის.

## შემოწმება

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe tests\smoke_mcp.py
```

17 შემოწმება ამოწმებს თანხებს, კურსის რაოდენობასა და მოქმედების თარიღს, თვისა და წლის ჯამებს, განმეორებით ჩანაწერებს, ანგარიშსა და პერიოდს, ფორმის ცვლილებებსა და სხვა თანხების დაცვას. STDIO შემოწმება უკავშირდება რეალურ MCP სერვერს მხოლოდ სინთეზური ადგილობრივი მონაცემებით. იგი ბრაუზერს არ ხსნის და არაფერს აგზავნის.

`tests/smoke_mcp.py --live` დამატებით ამოწმებს ეროვნული ბანკის საჯარო კურსის მიღებას. RS.GE-ის ავტომატური შევსება რეალური თანხებით და წარდგენა ჯერ არ არის გამოცდილი.

## Git-ში შენახვა

Git-ში ინახება კოდი, ტესტები, დამოკიდებულებების სია და კონფიგურაციის მაგალითები. `.gitignore` გამორიცხავს პირად ბაზას, `.env` ფაილებს, ბრაუზერის სესიის ფაილებს, ჟურნალებს, პირად ჩანაწერებსა და ადგილობრივ კონფიგურაციას. უკვე Git-ში დამატებულ ფაილს მხოლოდ `.gitignore` ვერ ამოიღებს.

პირადი გამოყენებისთვის რეკომენდებულია GitHub-ის private რეპოზიტორია. GitHub ინახავს კოდსა და ვერსიების ისტორიას; MCP პროცესის გასაშვებად საჭიროა კომპიუტერი ან შესაბამისი სერვერი.

აღრიცხვის ბაზა შეინახება `RS_LEDGER_PATH` გზაზე, ან ნაგულისხმევად `private-data/incomes.sqlite3`-ში. ბაზისთვის ცალკე სარეზერვო ასლია საჭირო — Git-ში გამორიცხული ფაილები რეპოზიტორიის ასლში არ მოხვდება. სესიის კონკრეტული ჩანაწერები და ამ კომპიუტერის კონფიგურაცია, თუ არსებობს, ინახება `.local.md` და `*-config.local.*` ფაილებში და Git-ში არ ემატება.

## რა აკლია გაგზავნას

1. რეალური მონაცემებით ფორმის შევსების შემოწმება, წარდგენის გარეშე.
2. შენახვის, გადახედვისა და საბოლოო გაგზავნის სრული პროცესის დამუშავება.
3. კონკრეტული ანგარიშის, თვის, თანხებისა და გადასახადის გადახედვა და მომხმარებლის მიერ გაგზავნის დადასტურება.
4. RS.GE-ის პასუხიდან რეგისტრაციის ნომრის, სტატუსისა და წარდგენის თარიღის გადამოწმება.
5. სესიის გათიშვისა და გაურკვეველი პასუხის დამუშავება: განმეორებითი გაგზავნის წინ სტატუსი მოწმდება, რათა ერთი მოთხოვნა ბრმად არ განმეორდეს.

გაგზავნის კოდის დამატება ცალკე სამუშაოა. ამ ვერსიას წარდგენა არ შეუძლია.
